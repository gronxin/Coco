# Codex 浮窗折叠与导航栏入口设计

## 目标

在不注入或修改 Codex 应用进程的前提下，缩小额度浮窗占用面积，并让入口在视觉上融入 Codex 左侧导航栏。

## 已确认方案

采用独立 `NSPanel` 覆盖层：

- 导航按钮仅在 Codex 位于前台时显示。
- 按钮尺寸为 36×36，贴合 Codex 左侧导航栏底部区域，不使用浮窗阴影。
- 点击按钮切换额度浮窗的显示与隐藏。
- 额度浮窗锚定当前 Codex 前台窗口右上角。
- Codex 位于前台时每 0.1 秒读取一次窗口位置，使按钮和浮窗跟随窗口移动、缩放和跨屏切换。
- Codex 退到后台时停止高频跟随并隐藏按钮和浮窗，但不改变用户的显示意图；回到 Codex 后恢复离开前的显示状态。
- 按钮和浮窗都使用非激活面板，点击后不抢走 Codex 的前台状态。

不采用以下方案：

- Accessibility `AXObserver`：事件驱动更省资源，但需要用户授予辅助功能权限。
- 进程注入或修改 Codex 资源：可以真正加入原生导航树，但安全风险高，且 Codex 升级后容易失效。

## 任务队列折叠

- 任务队列标题行是折叠开关。
- 展开时显示待执行任务总数和前五条任务标题。
- 折叠时隐藏标题和任务文本，仅显示可点击的“`N 个任务`”数量行。
- 待执行数量沿用当前浮窗的过滤口径，不包含 `completed`、`failed`、`dispatched` 和 `watching`。
- 折叠状态写入浮窗专用 `UserDefaults`，重启后恢复。
- 折叠和展开时动态调整面板高度，并保持面板右上角锚点不变。
- 折叠后的面板高度必须小于展开态。

## 窗口行为

- 导航按钮始终作为入口存在，不再使用“取消展示后出现恢复按钮”的双态结构。
- 浮窗是否显示与任务队列是否折叠是两个独立状态。
- 点击导航按钮显示浮窗时，恢复上次折叠状态。
- 点击浮窗中的额度区域打开用量总览；点击任务条目打开任务队列页面。
- 浮窗仍可拖动；用户拖动后停止自动右上角锚定并保存相对 Codex 窗口的位置，因此 Codex 窗口继续移动时浮窗仍会跟随。

## 状态模型

持久化域为 `UserDefaults(suiteName: "local.codex-token-analyzer.overlay")`：

| 状态 | 存储键 | 类型 | 默认值 | 写入时机 |
|---|---|---:|---:|---|
| 用户希望浮窗显示 | `overlayVisible` | Bool | `false` | 点击导航按钮 |
| 任务区折叠 | `queueCollapsed` | Bool | `false` | 点击任务数量或标题区域 |
| 使用自定义位置 | `customPosition` | Bool | `false` | 用户完成浮窗拖动；位置失效并回退时重置 |
| 相对横向偏移 | `panelRelativeX` | Double | 不存在 | 用户完成浮窗拖动 |
| 相对纵向偏移 | `panelRelativeY` | Double | 不存在 | 用户完成浮窗拖动 |

`appForeground`、`validTargetWindow` 和当前目标窗口矩形是运行时状态，不持久化。旧版 `hiddenByUser`、`windowOriginX` 和 `windowOriginY` 不迁移、不删除，也不再参与显示和定位判断。

可见性规则：

- 导航按钮可见：`appForeground && validTargetWindow`。
- 浮窗可见：`appForeground && validTargetWindow && userWantsOverlayVisible`。
- Codex 进入后台时只隐藏面板，不修改 `userWantsOverlayVisible`。
- 点击非激活面板不会改变 `appForeground`。

上述用户状态全局共享，不按 Codex 窗口分别保存。旧版 `hiddenByUser` 不再参与显示判断。

完整状态矩阵：

| 条件或事件 | 目标窗口 | 导航按钮 | 浮窗 | 0.1 秒跟随 |
|---|---|---|---|---|
| Codex 不在前台 | 无 | 隐藏 | 隐藏 | 停止 |
| Codex 在前台，无有效窗口 | 无 | 隐藏 | 隐藏 | 运行，等待窗口出现 |
| Codex 在前台，有有效窗口，`overlayVisible=false` | 最前有效窗口 | 显示 | 隐藏 | 运行 |
| Codex 在前台，有有效窗口，`overlayVisible=true` | 最前有效窗口 | 显示 | 显示 | 运行 |
| 当前目标最小化或关闭，仍有其他有效窗口 | 切换到下一个最前窗口 | 重新定位 | 按显示意图重新定位 | 继续 |
| 当前目标最小化或关闭，无其他有效窗口 | 无 | 隐藏 | 隐藏 | 继续等待 |
| 切到另一个 Codex 窗口 | 新的最前窗口 | 0.2 秒内重新定位 | 0.2 秒内重新定位 | 继续 |

## 目标窗口与边界

- Codex 在前台时，从 `CGWindowListCopyWindowInfo(.optionOnScreenOnly, ...)` 的前后顺序中选择第一个属于 Codex PID、窗口层级为 0、尺寸有效的窗口，作为当前目标窗口。
- 切换 Codex 窗口后，下一个 0.1 秒跟随周期重新选择目标并定位。
- 窗口最小化、关闭或不在当前 Space 时不会出现在候选列表；没有有效窗口时按钮和浮窗均隐藏。
- 默认浮窗位置为目标窗口右上角内缩 16 点、顶部内缩 42 点；导航按钮位于左侧栏底部、用户头像上方。
- 默认锚定模式在窗口缩放时重新计算右上角位置。
- 目标屏幕选择与目标窗口交集面积最大的 `NSScreen`；交集相同时使用主屏幕。
- 默认位置、自定义位置和导航按钮最终都钳制在目标屏幕的 `visibleFrame` 内。
- 自定义位置按目标窗口左下角偏移恢复；如果窗口、屏幕布局或显示器断开导致位置无效，则先钳制到目标屏幕的 `visibleFrame`。仍无法容纳时重置 `customPosition` 并回退到默认右上角位置。
- 目标窗口尺寸小于 120×120 点时视为无效窗口，避免按钮和浮窗在极小窗口中重叠。
- 坐标转换支持带负坐标的左右、上下排列显示器；全屏窗口使用目标窗口边界定位。

## 验证

- `swiftc` 编译通过。
- 重新安装 LaunchAgent 后进程持续运行，错误日志为空。
- `/api/quota` 与 `/api/night-queue` 返回成功。
- 在真实 Codex 窗口中验证按钮位于左侧导航栏、点击可切换浮窗。
- 连续拖动 Codex 窗口时，按钮和浮窗在 0.2 秒内跟随；停止拖动后位置与目标锚点一致。
- 缩放、全屏、跨屏移动和切换多个 Codex 窗口时，按钮与浮窗跟随当前目标窗口。
- 最小化或关闭当前窗口后，有其他有效 Codex 窗口时切换目标；没有有效窗口、切换 Space 或切到其他应用后面板隐藏。返回有效 Codex 窗口后恢复用户先前的显示意图。
- 点击按钮和浮窗不改变 Codex 的前台应用状态。
- 验证 0、1、5 和超过 5 条待执行任务：数量显示总数，展开态最多显示五条。
- 折叠任务区后只显示“`N 个任务`”，面板高度缩小；重启浮窗后折叠状态仍保留。
- 拖动浮窗后移动 Codex 窗口，浮窗保持相对位置；显示器断开或保存位置失效时不出屏。
- 在左右排列、上下排列、负坐标、部分出屏和小窗口场景中验证目标屏幕选择与边缘钳制。
- 通过活动监视或定时器状态确认 Codex 退到后台后不再执行 0.1 秒跟随。
- 只有以上实现和验收通过后，才用新行为替换主 PRD 中旧的浮窗事实。
