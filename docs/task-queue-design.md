# Codex 额度驱动任务队列：功能设计稿

## 目标与边界

用户可随时录入并排序任务，手动开启“任务队列”。系统在本机持续观察 Codex 的 5 小时额度和较长周期额度；额度可用时，依次启动队列任务。额度不足时等待官方返回的重置时间，届时重新查询，确认可用后再启动下一项。队列可全天持续运行；用户关闭后，后续任务不再自动启动。

这里的“新建任务”指独立的本地 Codex 对话。队列开启后自动扫描本机未归档主对话的最新轮次；只有发现结构化额度耗尽错误、且实时额度恢复可用，才续接原对话。任务 ID 手动托管仅作为补充入口。每次仅运行一项；**完成后只要额度仍有余量，就立即启动下一项**，无需强制等下个 5 小时窗口。

## 使用流程

1. 在“任务队列”页添加任务：标题、完整指令、工作项目或目录、模型、思考深度、执行顺序。界面展示实际将发送的指令和模型配置，避免把简写标题误当指令。可重排、编辑、删除待执行项。
2. 确认项目目录和队列，然后开启；只有用户主动关闭才停止监控与派发。页面显示五小时与周额度、数据更新时间、当前任务、下一任务及下一次检查时间。
3. 后台先刷新额度。两个适用额度窗口都有余量、数据新鲜且没有其他队列任务运行时，校验队首任务所选模型和思考深度仍可用，原子认领并按该配置启动一个 Codex 任务。浏览器关闭后，后台仍应继续工作。
4. 任务完成后记录结果、Codex 对话链接、实际使用的模型与思考深度、开始/结束时间和本系统采集到的 token。重新查询额度；满足条件就立即继续下一项，不满足则等重置或用户处理。如果任务**执行中**因明确的账户额度耗尽而失败，则保留该任务及原 Codex 对话；重置后先在原对话继续未完成工作，完成后才派发下一项。

## 逐任务模型配置

队列设置提供一个可选的“默认模型 + 默认思考深度”；每个任务可选“继承队列默认值”或单独指定一组模型与思考深度。任务卡片始终显示最终生效的组合，例如“模型 A · high”，任务配置页逐项列出，防止配置在长队列中被忽略。编辑队列默认值时，仅更新仍选择“继承”的待执行任务；已经运行或完成的记录不变。可选增加“复制上一项配置”以便连续创建相似任务。

模型和思考深度选项从当前 Codex 的 `model/list` 获取，思考深度只列出对应模型声明支持的值；不硬编码一个对所有模型通用的列表。切换模型时，如果原思考深度不受支持，要求重新选择或明确采用该模型默认值。派发前重新校验可用性；模型下线、账户无权限或组合不受支持时，标记该项“配置需要处理”并暂停队列，**不擅自换成其他模型或降低思考深度**。额度归属无法确认时同样暂停。

执行记录保存用户选择的配置、派发时实际提交的配置及 Codex 返回或日志可核验的实际模型；若实际值与预设不一致，显示差异。对旧任务或日志无法确认思考深度时显示“未知”，不从模型名称推断。模型选择只影响该队列项，不改动 Codex 的全局默认配置或其他对话。
5. 用户关闭队列后停止监控和**新任务派发**；已开始的任务继续至本轮结束，不会再启动下一项。
6. 按需查看运行报告：完成、失败、等待额度及需要人工处理的任务；可从报告进入 Codex 原任务继续工作。

## 派发规则

“可派发”同时满足：队列已开启、存在待执行项、无在运行的队列任务、最新额度查询成功且足够新鲜、五小时和周额度均有余量。不设置保留比例；即使接近用尽也可继续派发，**不能保证任务一定能在剩余额度内完成**。额度只提供窗口已用百分比，不是可精确兑换的 token 数。

查询失败、额度字段缺失或快照过期时不派发。后台每分钟检查；五小时额度耗尽时展示服务端当前的 `resetsAt`，每次复查都重新读取额度。若重置时间改变，展示随之更新；即使原预计时间尚未到，只要实时额度已恢复也可续接。周额度耗尽同样等待。任务启动前和结束后都即时刷新一次。

不同服务层或额度桶可能并存，派发条件只使用实际将运行的 Codex 任务所对应的额度桶；无法确认对应关系时暂停并标注“额度归属未知”。若用户白天也在其他 Codex 对话消耗额度，队列以最新服务端值为准。任务前后的额度差值仅标注为“期间观察到的变化”，不能直接归因给这个任务；任务自身 token 仍由本地日志账本核算。

## 状态与异常

队列总状态：关闭、监控中、运行中、等待五小时额度、等待周额度、需要处理、数据不可用。任务状态：待执行、监控已有对话、已认领、运行中、等待额度续接、正在续接、已完成、失败、需要处理、已取消。模型配置失效属于“需要处理”。每个新建任务只创建一次 Codex 对话；已有对话通过本机元数据自动发现。仅收到结构化的 `UsageLimitExceeded` 或实际 app-server 返回的 `usageLimitExceeded` 时，才自动在原对话续接；普通失败、连接断开、审批或重启后的不确定状态由用户核查。续接前再次核对原轮次未被其他操作推进，并刷新五小时和周额度；续接提示要求先核对已有工作，只做剩余部分。

Codex 要求审批、补充输入或遇到权限限制时，保留原对话并暂停队列，页面显示阻塞原因。系统不自动批准权限请求。服务进程重启后，依据持久化的任务 ID、对话 ID 和运行 ID 恢复监听或核对状态；无法确定任务是否已启动时进入“需要处理”，不能再创建第二份。用户手动关闭队列后，正在运行的任务完成也不能触发下一项。

持续执行依赖本机服务运行、网络可达且电脑保持唤醒；Mac/Windows 进入睡眠或关机后，本地监控和派发都会暂停。恢复唤醒时重新查询额度与任务状态后继续，不补发过去窗口里原本可能启动的任务。

## 页面与记录

总览新增紧凑状态卡：开关、当前状态、五小时/周额度、预计复查时间、当前任务及其模型配置、队首任务及其模型配置、上次成功查询时间。新增队列页：任务编辑和排序、队列默认模型配置、逐任务覆盖、启动/关闭、运行历史、阻塞原因。运行报告按“启动时间—任务—预设/实际模型配置—额度快照—执行结果—实际 token—可打开的 Codex 对话”排列。

本地数据库新增队列项、运行记录、额度快照和派发器状态。队列项保存模型 ID、思考深度以及“继承/覆盖”关系；运行记录保存派发时冻结的配置，确保后来编辑默认值不会改写历史。队列项也会保存用户主动录入的完整任务指令，这是现有用量账本“不保存对话正文”的**明确例外**；页面需说明，提供删除和清空历史，数据库仅在本机保存，并限制文件权限。不读取或保存认证文件，不上传日志。报告保留执行状态和安全摘要，不复制完整 Codex 对话或工具输出。

## 技术落点

沿用现有 `codex app-server` 额度读取链路；增加独立后台派发器，由后端进程维护，不依赖网页定时器。派发器使用持久化状态和数据库事务完成认领，保证重启或并发检查时只创建一次。使用 `model/list` 获取当前账户可用模型及其思考深度；启动执行采用 app-server 的新对话与新轮次接口，在 `turn/start` 明确传入逐任务的 `model` 和 `effort`，并监听完成状态。先做兼容性验证，确认该方式创建的任务在用户的 Codex 客户端中可见并能继续操作。若可见性不符合要求，不能把“已提交给 Codex”视为体验验收通过。

首版只支持本机一个派发器实例和一个同时运行的队列任务。项目目录必须在用户指定且可访问的范围内；执行权限沿用 Codex 当前配置，不为了无人值守而自动扩大权限。发布、外发消息和其他不可逆操作由任务自身的权限规则处理；遇到所需确认就暂停等待用户。

## 验收场景

- 有两项待执行任务且额度充足：只启动第一项；第一项结束且额度仍有余量时启动第二项，全程不并发、不重复。
- 第一项中途收到 `UsageLimitExceeded`：保存原对话 ID、轮次 ID 和重置时间，第二项保持待执行；重置并核验额度后先通过 `thread/resume` 续接第一项，第一项完成后才启动第二项。服务重启后仍遵守该顺序。
- 普通 429、网络中断或上次轮次状态不明：不得当成五小时额度耗尽自动续接，展示“需要处理”。
- 两项任务分别选择不同模型和思考深度：派发请求和运行记录各自使用对应配置；队列默认值的修改不会改变已运行记录。
- 模型或思考深度在配置后失效：该任务不自动降级或换模型，队列暂停并说明需要修改的配置。
- 五小时额度耗尽：不启动；到 `resetsAt` 后若刷新成功且两类额度均有余量，启动队首任务；刷新失败则继续等待并显示原因。
- 周额度耗尽：即使五小时额度已重置，也不启动任务。
- 关闭队列：停止监控和新任务派发，已运行任务完成当前轮次后结束。
- 后端重启、浏览器关闭、电脑睡眠再唤醒：状态可恢复，任何队列项最多自动启动一次。
- Codex 要求审批、执行失败、额度数据过期：暂停并明确展示阻塞原因，不自动重试或假报完成。
- 报告中的额度百分比与本地 token 用量分别标明来源，不把窗口额度差值说成单个任务的精确消耗。

## 实施前需确定的产品选择

已确定采用“每项新建独立任务、串行执行、结束后若额度仍可用就继续”；支持队列默认模型配置与逐任务覆盖。如果以后希望**所有项续在同一 Codex 对话**，派发与恢复规则需要相应调整。其他建议默认值为：手动开启、无自动关闭时间、关闭时让当前任务完成、遇到失败或审批暂停队列。
